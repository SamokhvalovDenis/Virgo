Актуальний стан містять [PRE_LAUNCH_REPORT.md](../PRE_LAUNCH_REPORT.md), [DEPLOYMENT.md](../DEPLOYMENT.md) і [contact-form-testing.md](contact-form-testing.md). ## Стан

Реалізовано React/TypeScript landing чеською мовою: Header, Hero, 4 категорії з розкривними процедурами, прайс із 27 позицій, About, GiftCards, Pluxee, Contact і Footer. Reviews та FAQ відображаються лише за наявності даних. Контакти й адреса надані користувачем: вони відображаються в Contact і Footer, а графік із приміткою — у Contact. Посилання на Google Maps формується за наданою адресою.

Файлів AGENTS.md та README-VIRGO.md не було в наданому checkout. Прочитано всі початкові 8 Markdown-файлів docs/ та src/data/README.md. README.md був стартовим Vite-шаблоном.

## Запуск

- npm install (або npm ci для відтворення package-lock.json).
- npm run dev — локальна розробка.
- npm run typecheck — строгий TypeScript для UI, Vite-конфігурації та Functions.
- npm run lint — ESLint.
- npm test — ціни проти документації, серверний HTML, валідація, заглушка API.
- npm run build — production у dist/.
- npm run preview — перегляд production.

У Windows PowerShell з обмеженою execution policy використовуйте npm.cmd замість npm. Не вимикайте перевірку TLS-сертифікатів; за потреби встановіть довірений корпоративний сертифікат або використайте системне сховище Node.

## Дані та зображення

Бізнес-контент, CTA, доступні назви елементів, налаштування і посилання зберігаються в src/data/. CSS-токени — у src/styles/index.css; локальні OFL-шрифти з чеськими символами — у src/styles/fonts.css. Жодних Google Fonts запитів.

Фото наразі відсутні. Замість чужих або згенерованих інтер'єрів використано оригінальний декоративний SVG/CSS. Для додавання справжніх фото покладіть оптимізовані WebP/AVIF до public/images/ і заповніть assets.ts. Компонент приховує відсутні й пошкоджені зображення. Фото карток і нижніх секцій завантажуються ліниво; Hero має пріоритет.

Подарунковий ваучер — декоративна ілюстрація з явним підписом. Для справжнього фото підпис автоматично приховується.

## Контактна форма: інтеграцію навмисно вимкнено

settings.contact.enabled = false. Форма має поля, вибір процедур, автоматичний вибір теми подарункового сертифіката, Zod-схему та підготовлені стани. Надсилання вимкнено й пояснено відвідувачу. Дані не зберігаються в localStorage та не передаються мережею.

functions/api/contact.ts — Cloudflare Pages Functions заглушка у корені; POST повертає 503, інші методи — 405. Немає фіктивного успіху, Resend-запитів або обробки персональних даних.

Перед активацією:
1. Отримати реальні контакти та затверджений privacy-текст.
2. Додати на сервері перевірку origin, JSON Content-Type, обмежений за розміром reader, спільну contactSubmissionSchema і rate limit.
3. Підключити Turnstile UI та обов'язкову серверну перевірку токена.
4. Додати Resend на сервері; секрети RESEND_API_KEY, TURNSTILE_SECRET_KEY, CONTACT_FROM, CONTACT_TO — лише в Cloudflare.
5. Використовувати підтверджений домен відправника, email клієнта — як reply-to. Відповідати success:true лише після прийняття листа провайдером.
6. Перевірити доставку на реальну пошту й помилки; заповнити settings.contact.privacyUrl і лише тоді enabled.

Звичайний Vite dev не запускає Functions. Для майбутнього API потрібне сумісне середовище Cloudflare Pages/Wrangler.

## SEO та публікація

Чеські title/description/Open Graph генеруються Vite із site.ts. lang=cs, favicon і robots.txt готові. Canonical і sitemap.xml генеруються лише після заповнення site.seo.canonicalUrl справжнім production URL. Без підтвердженої адреси/телефону не додається LocalBusiness schema.

Cloudflare Pages: build npm run build, output dist, functions/ у корені. Автоматичного деплою, зміни домену чи підключення сторонньої аналітики не виконано.

Аналітика за замовчуванням вимкнена. Підготовлено opt-in подію virgo:booking-click з місцем кнопки без персональних даних; це клік, а не підтверджене бронювання.

До комерційного релізу залишаються підтвердження власниці щодо прайсу й методик, 12 місяців сертифіката, Pluxee, фото, контактів, домену, чеської редактури та privacy. Ручна браузерна перевірка на 360/390/768/1280px потрібна окремо, якщо браузерні інструменти недоступні у середовищі.

## Виправлення `504 Outdated Optimize Dep`

Dev-сервер на localhost:5173 віддавав старі URL оптимізованих React-модулів, а каталог `node_modules/.vite/deps` був відсутній. Помилку 504 відтворено HTTP-запитом.

Для SSR-тестового Vite-сервера виділено `cacheDir: node_modules/.vite-tests`, щоб тестовий запуск не перебудовував і не видаляв кеш відкритого dev-сервера. У головній конфігурації явно вказані React entry points для `optimizeDeps.include`. Зміна конфігурації перезапустила активний Vite і відновила його кеш без видалення node_modules чи lockfile.

Перевірено: React, react-dom/client і JSX dev runtime повертають 200. Після запуску 13 тестів хеш dev-метаданих не змінився, і ті самі URL залежностей продовжили повертати 200. TypeScript, ESLint і production build проходять.

Якщо вкладка ще тримає старий query hash, оновіть її через Ctrl+Shift+R. Для ручного відновлення після майбутньої зміни залежностей можна зупинити dev-сервер і запустити `npm.cmd run dev -- --force`, потім оновити вкладку. Постійний `force: true` у конфігурацію не додається.
