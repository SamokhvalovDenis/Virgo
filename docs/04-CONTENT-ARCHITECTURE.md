# 04. Модель контенту: все змінюється у `src/data/`

## Основний принцип

**UI-компоненти нічого не знають про бізнес-тексти.** Вони лише виводять об'єкти з окремих TypeScript-модулів. Ні назви послуги, ні Kč, ні кнопки, ні телефон не живуть у JSX як константні рядки.

Переваги:
- змінити прайс — відкрити один `prices.ts`;
- змінити послугу — `services.ts`;
- змінити текст банера — `content.ts`;
- змінити Termino, номер, соцмережі — `site.ts`;
- додати відгук — `reviews.ts`, не торкаючись макета.

Це **не CMS**. Зміни `.ts` збираються в нову статичну версію сайту після `git push` і нового деплою.

## Мапа “що редагувати”

| Зміна | Файл | Примітка |
|---|---|---|
| Назва, місто, телефон, email, адреса | `src/data/site.ts` | `null` якщо невідомо |
| Посилання на Termino | `src/data/site.ts` | тільки одна точка правди |
| Кольори й шрифти | `src/styles/index.css` | design tokens, не бізнес-контент |
| Навігація, Hero, підписи CTA, About | `src/data/content.ts` | тексти чеською |
| Групи послуг, порядок секцій-категорій | `src/data/categories.ts` | стабільні id |
| Перелік і назви конкретних процедур | `src/data/services.ts` | `title` — єдине джерело назви для сторінки та пов'язаних рядків прайсу |
| Повні описи й фото процедур | `src/data/serviceDetails.ts` | назви послуг підставляються за `id` через `serviceHeading` |
| Прайс депіляції | `src/data/prices.ts` | зі скриншота; підтвердити |
| Відгуки | `src/data/reviews.ts` | порожній масив = секцію сховати |
| FAQ | `src/data/faq.ts` | лише перевірені відповіді |
| Сертифікати | `src/data/giftCertificates.ts` | строк уточнити |
| Програма Pluxee | `src/data/benefits.ts` | не фейковий logo |
| Фото | `src/data/assets.ts` + `public/images` | тільки перевірені файли |

## Структура даних та правила

### `site.ts`
```ts
export type SiteConfig = {
  name: string;
  city: string;
  phone: string | null;
  email: string | null;
  streetAddress: string | null;
  bookingUrl: string;
  googleMapsUrl: string | null;
  social: { instagram: string | null; facebook: string | null };
};
```

### `services.ts`
Кожна послуга містить стабільний `id`, `categoryId`, назву чеською, короткий опис, можливо кілька уточнень, зображення (ID або `null`), та статус відображення. **Не плутати** `categoryId="depilation"` і різні технології `sugaring`, `waxing`.

Назву редагують тільки в полі `title` у `services.ts`. `getServiceTitle(id)` повертає її для сторінок і відповідних позицій прайсу; невідомий `id` спричиняє помилку під час збірки. `sourceTitle` в описах і назви у відгуках зберігають історичний текст. Самостійні позиції прайсу та інформаційні заголовки мають власні підписи. Приклад редагування: [src/data/README.md](../src/data/README.md#як-змінити-назву-послуги).

### `prices.ts`
Ціна — або **точне число**, або **діапазон**, або `null`. Не використовувати 0 для невідомої ціни.
```ts
type PriceValue = number | { from: number; to: number } | null;
type PriceRow = {
  id: string;
  groupId: string;
  label: string;
  women: PriceValue;
  men: PriceValue;
};
```
- Крону додає UI через форматер, вона не є частиною числових даних.
- Одна валюта: `CZK`.
- Будь-які зміни цін мають походити від власниці.
- Скріншот **сам по собі не доводить**, чи ці ціни однаково діють для воскової депіляції та шугарингу. Це запитати.

### `reviews.ts`
Реальна цитата, автор (за дозволом), джерело, дата або `null`, посилання на джерело за наявності; без вигаданого рейтингу.

### `content.ts`
UI labels і секційні тексти тримати окремо. Принцип “один ключ — одне значення”. Уникай дублювання «Rezervovat termín» у 7 компонентах.

## Локалізація

**V1:** тільки `cs-CZ`; `.md` пояснення українською.  
**V2, якщо попросять:** окремі словники `src/data/i18n/cs.ts`, `.../en.ts`. Не переписувати всю структуру “про всяк випадок”.

## Коли потрібна CMS

Якщо власниця хоче сама регулярно (наприклад щотижня) редагувати прайс і акції, `.ts` — не дуже підходящий інтерфейс, бо потрібен Git/deploy. Тоді вже обговорити Sanity / Decap CMS / інший редактор. **Не впроваджувати зараз.**

## Публікація змін

1. Відредагувати дані.
2. `npm run build`.
3. Перевірити локально.
4. `git add . && git commit -m "Update prices"` та `git push`.
5. Git-integrated Cloudflare Pages створює нову збірку.
6. Перевірити продакшн.

Не зберігати ні токени email-сервісу, ні повідомлення клієнтів у `src/data`.
