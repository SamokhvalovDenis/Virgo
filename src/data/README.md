# Як редагувати сайт без зміни React-компонентів

Усі файли тут — типізовані **TypeScript модулі**. Їх імпортують React-компоненти.

1. `site.ts` — контакти, бронювання, місце, соцмережі.
2. `content.ts` — навігація, назви секцій, Hero, кнопки.
3. `categories.ts` — групи послуг і їхній порядок.
4. `services.ts` — конкретні процедури та єдине місце редагування їхніх назв (`title`). Сторінки послуг і пов'язані позиції прайсу беруть назви через `getServiceTitle(id)`.
5. `prices.ts` — **137 рядків / 198 цінових значень** у 4 категоріях: депіляція, масажі й обгортання, апаратне видалення волосся та пакети, брови/вії. Початкові 27 позицій депіляції залишені без змін.
6. `reviews.ts` — 9 наданих відгуків із паперової книги студії без даних авторів. `StudioReview` містить унікальний `id`, справжні `rating`, повний `text`, назву процедури `service`, `source: 'guestbook'` та необов'язкову `date` (YYYY-MM-DD, лише якщо надана). У поточних записах дат немає; компонент приховує їх. Не додавайте авторів, ініціали, фото, підписи, контакти чи URL джерела; не змінюйте оригінальні тексти й оцінки. Джерело показується звичайним текстом. Порожній масив приховує секцію та її пункт меню. Документи згоди зберігаються власницею окремо від репозиторію й frontend. Список даних для завершення політики: [reviews-privacy.md](../../docs/reviews-privacy.md).
7. `faq.ts` — також порожній масив, поки немає затверджених відповідей.
8. `giftCertificates.ts` — умови сертифікатів (строк підтвердити).
9. `benefits.ts` — Pluxee (актуальність підтвердити).
10. `assets.ts` — шляхи до реальних фото, метадані, галерея та тип `AssetKey`. Значення `null` зберігає передбачений декоративний варіант.
11. Контракти категорій, послуг, сайту й FAQ розташовані у відповідних модулях; контракти прайсу — у `prices.types.ts`. `index.ts` експортує публічні дані й типи для тестів; компоненти використовують прямі імпорти.
12. `settings.ts` — форма, адреса її API, затверджене privacy-посилання й opt-in аналітика. Надсилання за замовчуванням вимкнено.
13. `navigation.ts` — навігація з автоматичним приховуванням відсутніх відгуків і вимкнених сертифікатів.
14. `serviceDetails.ts` — повні чеські описи 18 інформаційних блоків, чотири URL, фото оригіналу та внутрішні позначки тверджень, які має перевірити власниця. `needsApproval` позначає конкретний абзац або пункт списку лише в даних; редакторські позначки й пояснення на публічних сторінках не показуються. Порядок блоків і фото звірено з HTML джерела; приблизні підписи старого звіту зображень іноді зсунуті на сусідню процедуру. Див. `reports/virgo-service-details-audit.md`.
15. `about.ts` — секція «O nás»: `eyebrow`, `title`, масив `paragraphs`, масив `benefits`, `ctaText` і `gallery`. Фото та їхній порядок беруться з `aboutGallery` у `assets.ts`; перше фото — головне, наступні два — праворуч, останні три — нижній ряд на desktop. URL бронювання залишається спільним у `site.links.booking`.

## Структура `site.ts`

- `name` — назва студії для Hero, доступної назви логотипа, footer і SEO.
- `location` — вулиця, місто, індекс, країна та повна адреса. За повною адресою автоматично формується посилання на Google Maps; без вулиці/повної адреси карта не показується.
- `contact.phone` / `contact.email` — видимі контакти. `phoneHref` / `emailHref` — їхні посилання; якщо посилання `null`, вони формуються з номера/email автоматично. Якщо змінюєте контакт із явно заданим href, оновіть також href.
- `openingHours` — масив `{ day, hours }`, один рядок графіка на день. Для вихідного можна вказати `Zavřeno`.
- `hoursNote` — окрема примітка під графіком, або `null`.
- `links.booking` — єдине джерело URL Termino для всіх кнопок запису.
- `links.website`, `links.facebook`, `links.instagram` — посилання у footer; `null` приховує відповідний пункт.
- `locale` — локаль форматування цін, зараз `cs-CZ`.
- `seo.title` / `seo.description` — metadata. `seo.canonicalUrl` — адреса нової production-версії, або `null` до публікації. Оригінальний сайт у `links.website` не підставляється замість canonical.

Об'єкт перевіряється типом `SiteConfig`: випадкова зміна назв полів буде видима під час TypeScript-перевірки. Контактна секція й footer використовують спільний компонент `ContactDetails`.

## Як змінити назву послуги

У `services.ts` знайди послугу за стабільним `id` і зміни тільки `title`:

```ts
id: "massage-chocolate",
categoryId: "massage",
title: "Čokoládová masáž",
```

Ця назва автоматично використовується в заголовку на сторінці масажів і в рядку прайсу. Не змінюй `id` для перейменування. У `serviceDetails.ts` виклик `serviceHeading(id)` підставляє назву; у `prices.ts` її підставляє `getServiceTitle(id)`. Тривалість, ціни й доповнення пакетів редагуються в `prices.ts`. Наприклад, назва масажу в пакеті з озоновим обгортанням оновлюється разом із назвою окремої послуги.

`sourceTitle` у `serviceDetails.ts` зберігає історичний заголовок оригіналу для аудиту. Назви всередині справжніх відгуків і текстові описи не перейменовуються автоматично. Два інформаційні блоки про видалення волосся мають власні заголовки, бо це не назви послуг. Позиції прайсу з окремим змістом (зони тіла, комбіновані процедури) мають власні `label` у `prices.ts`.

## Приклад зміни ціни

`priceCatalogs` визначає категорії та групи для інтерфейсу. `depilationPrices` зберігає початкові 27 рядків, `additionalDepilationPrices` — додаткові зони та комбінації. `massagePrices` і `browsLashesPrices` мають поле `price`; `deviceHairRemovalPrices`, `deviceHairRemovalPackages` і депіляція — `women` / `men`.

`detail` зберігає тривалість або кількість відвідувань. `note`, `womenNote`, `menNote` — примітки, зокрема заставу. Не розраховуйте нові ціни з вартості пакета. `sourceIds` посилаються на `priceSources` — локальні оригінали для перевірки, а не фотографії, які показує прайс.

У гендерному прайсі `null` означає, що в джерелі немає ціни для цієї статі: рядок приховується для неї. Не копіюйте ціну іншої статі. Повний аудит і таблиці перенесених сум: [virgo-price-audit.md](../../reports/virgo-price-audit.md).

У `prices.ts` знайди `id: "depilation-arms-full"`:
```ts
{ id: "depilation-arms-full", groupId: "arms", label: "Celé ruce",
  women: 550, men: { from: 750, to: 850 } }
```

Власниця підтвердила нову вартість? Зміни лише `women`, `men`. Ні `PriceList.tsx`, ні стилів чіпати не треба.

## Як додати або прибрати примітку в прайсі

У `prices.ts` знайди потрібну позицію за `id` та додай поле `note` з погодженим текстом чеською. Назву (`label`), тривалість (`detail`), ціну й ідентифікатор залиш без змін:

```ts
// Усередині потрібної позиції прайсу:
note: "Погоджений текст чеською",
```

Примітка з'явиться під ціною та кнопкою `Rezervovat`, з тонкою золотою лінією та іконкою інформації. Це працює для всіх масивів прайсу, включно з `depilationPrices`. `services.ts` для приміток прайсу змінювати не потрібно.

Для уточнення лише одного варіанта тривалості додай `note` тільки до його рядка. Для спільної примітки всієї картки додай `note` до відповідної групи в `priceCatalogs` (об'єкт із `id` та `title`, з якого формується `rows`). Вона з'явиться один раз після всіх цін групи. Наприклад, група `madero` містить кілька варіантів мадеротерапії. Не додавай спільний текст до кожного рядка. Якщо картка містить різні процедури, спільна примітка має стосуватися всіх її позицій; інакше використовуй примітку конкретного рядка.

`womenNote` / `menNote` задають текст для відповідної аудиторії замість спільного `note`. Відсутнє значення або `null` у цих полях використовує спільне `note`; порожній рядок приховує примітку для цієї аудиторії.

Щоб прибрати примітку, видали `note` або вкажи `note: null` чи `note: ""`. Пробіли також не показуються; лінія, іконка й зайві відступи не залишаються. Приклад із частинами тіла не прив'язаний до жодної процедури автоматично. Після редагування даних потрібна звичайна збірка та публікація сайту.

## Обмеження

- Значення `null` означає “невідомо / немає”; **не друкувати `null` клієнту** й не підміняти нульовою ціною.
- Жодних API ключів або персональних даних із форм у цій папці!
- Зміни в коді стають видимими після **нового деплою**, не через веб-адмінку.
